Guia ilustrada

Como usar Subscription Platform con una app como el CRM

Esta guia explica desde cero como configurar una aplicacion, crear planes, asignar suscripciones, generar un Service Token y usarlo para que el CRM pueda permitir o bloquear acceso.

Archivo generado para: subscription-platform. No contiene passwords ni tokens reales.

1. Idea general

Subscription Platform es el sistema central que decide si un cliente puede usar una aplicacion o un modulo. El CRM sigue siendo el CRM; esta plataforma solo le responde si debe permitir o bloquear acceso.

Regla importante: El CRM no debe leer tablas adm directamente. Debe preguntar a subscription-api usando el endpoint de validacion o el SDK.

3. Paso a paso: configurar el CRM en el admin

Paso 1 - Crear aplicacion CRM

  1. Entrar al admin web.
  2. Ir a Aplicaciones.
  3. Crear una aplicacion con codigo CRM.
  4. Agregar modulos separados por coma, por ejemplo: dashboard, customers, invoices, payments.

Paso 2 - Crear plan

  1. Ir a Planes.
  2. Seleccionar la aplicacion CRM.
  3. Crear un plan, por ejemplo CRM_PRO.
  4. Definir precio, moneda, frecuencia, dias de gracia y dias para suspension.

Paso 3 - Crear cliente

  1. Ir a Clientes.
  2. Crear el cliente con razon social, nombre visible y email.
  3. Dejar Suspension global = No si el cliente puede operar.

Paso 4 - Crear suscripcion

  1. Ir a Suscripciones.
  2. Seleccionar cliente, aplicacion CRM y plan.
  3. Definir fecha de inicio, proxima factura y dia de facturacion.
  4. Usar estado ACTIVE si el cliente ya puede entrar.

4. Crear Service Token para el CRM

El Service Token es la credencial que usara el backend del CRM para consultar POST /api/v1/entitlements/validate.

Muy importante: El token plano solo se muestra una vez al crearlo. Si se pierde, hay que revocarlo y crear uno nuevo. En base de datos solo queda el hash.
  1. Ir a Service Tokens.
  2. Seleccionar aplicacion CRM, o dejar Global si el token servira para varias apps.
  3. Nombre sugerido: CRM local dev token o CRM production token.
  4. Scopes: entitlements.validate.
  5. Crear token y copiar el valor que inicia con sat_.

Variables recomendadas en CRM_API_SERVER

SUBSCRIPTION_API_URL=http://localhost:3000/api/v1
SUBSCRIPTION_SERVICE_TOKEN=sat_xxxxxxxxxxxxxxxxx

5. Como el CRM valida acceso

El CRM debe validar acceso despues del login y tambien al entrar a modulos importantes. La validacion no reemplaza el login del CRM; solo decide si la suscripcion permite usar el sistema.

Ejemplo de llamada HTTP

POST http://localhost:3000/api/v1/entitlements/validate
Authorization: Bearer sat_xxxxxxxxxxxxx
Content-Type: application/json

{
  "customerId": "UUID_DEL_CLIENTE",
  "applicationCode": "CRM",
  "requestedModule": "dashboard"
}

Respuesta permitida

{
  "success": true,
  "data": {
    "allowed": true,
    "reason": null,
    "subscriptionStatus": "ACTIVE"
  }
}

Respuesta bloqueada

{
  "success": true,
  "data": {
    "allowed": false,
    "reason": "PAYMENT_OVERDUE",
    "subscriptionStatus": "SUSPENDED"
  }
}

6. Como bloquear o reactivar acceso desde el admin

Bloqueo manual

Ir a Suscripciones y presionar Suspender. Desde ese momento, la validacion debe devolver allowed: false.

SUSPENDED ADMINISTRATIVE

Reactivacion

Ir a Suscripciones y presionar Reactivar. Si la suscripcion vuelve a estar activa, el CRM puede permitir acceso.

ACTIVE allowed true

Bloqueo por pago

Si hay facturas vencidas y reglas de suspension, la validacion puede bloquear por deuda o mora.

PAYMENT_OVERDUE OUTSTANDING_BALANCE

Prorroga

Desde Prorrogas puedes extender el vencimiento de una factura y, si aplica, reactivar al cliente.

EXTENSION GRACE

7. Orden recomendado para una prueba completa

  1. Levantar subscription-api con npm run dev.
  2. Levantar subscription-admin-web con npm run dev.
  3. Iniciar sesion con el admin.
  4. Crear aplicacion CRM.
  5. Crear plan CRM_PRO.
  6. Crear cliente de prueba.
  7. Crear suscripcion activa.
  8. Crear Service Token para CRM.
  9. Ir a Accesos y probar la validacion con el Service Token.
  10. Suspender la suscripcion y repetir la validacion. Debe negar acceso.
  11. Reactivar la suscripcion y repetir la validacion. Debe permitir acceso.
